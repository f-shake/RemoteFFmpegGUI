# WPF 缩略图点击放大预览

## 目标

右侧任务卡片里的快照缩略图（360×256）目前只是静态显示，任务运行中每秒左右换一张，细节完全看不清。本次让**点击缩略图弹出一个独立窗口，在里面能放大、缩小、平移地看这一帧**。

Web 端已有等价能力（状态栏缩略图点开是 Element Plus 的 `el-image` 预览层），本次把 WPF 端补齐。

## 现状盘点

- 缩略图在 `SimpleFFmpegGUI.WPF/Panels/StatusPanel.xaml:52-66`：一个 360×256 的 `Border` 内嵌 `Image`，绑定 `Snapshot.Source`（`SnapshotViewModel`，`Uri` 类型）指向 `%TEMP%\SimpleFFmpegGUI\snapshot\{GUID}.jpg`；无任何交互。
- 图片由 `TaskInfoViewModel.UpdateSnapshotAsync`（`ViewModels/TaskInfoViewModel.cs:267-308`）在计时器里刷新，取的时间点是 `ProcessStatus.Time + (Inputs[0].From ?? TimeSpan.Zero)`；`FileSystemHelper.GetTempFileName` 每次返回新的 GUID 路径，WPF 侧从不删除这些文件。
- WPF 侧**没有**任何可复用的缩放/平移实现：全仓搜 `MouseWheel`/`ScaleTransform`/`MatrixTransform`/`RenderTransform`/`Viewbox` 只命中图标字形、AppBarButton 模板里的 Viewbox、以及 `FileIOPanel.xaml` 一个 `ScaleY="0"` 折叠动画；`ikw:`（iNKORE.UI.WPF）里只有 `SimpleStackPanel`/`VirtualizingWrapPanel` 等，没有看图控件；内化的 FzLib 只有平滑滚动。→ 自研。
- 独立窗口一律经 `SimpleFFmpegGUI.WPF/ViewWindow.cs`（设置 iNKORE 现代窗口样式、按属主窗口限初始尺寸、叠加加载环、支持 `ICloseableView` 与会话结束时 `Dispose`）。直接 `new Window()` 会因 iNKORE backdrop 递归导致 StackOverflow（`MainWindow.xaml.cs:329` 有备注）。
- `ViewModelBase.SetDataContext<TVM>()` 从 `App.ServiceProvider` 取 VM（`ViewModels/ViewModelBase.cs:71-77`），因此新 VM 需在 `App.xaml.cs` 注册。
- 项目没有 WPF 测试工程（`SimpleFFmpegGUI.UnitTests` 只引用 Core）。

## 行为约定（已逐条确认）

1. **冻结当帧**：窗口显示的是点击那一刻的那一张，不跟随后续刷新。
2. **复用 `ViewWindow`**，非模态，Owner = 主窗口。
3. **同一帧重复点击 → 激活已开窗口**（按快照文件路径去重，窗口关闭时移除）；不同帧/不同任务各开各的窗口。
4. **初始缩放 = min(适应比例, 1)**：图比窗口小时按原始像素居中，不放大。
5. **窗口改大小时**：仍处于"适应"模式则重新适应并居中；用户一旦滚轮缩放或切过 1:1，就进入"自由"模式，改窗口大小不再动缩放与位置。
6. **平移做钳制**：图比视口小则强制居中，比视口大则把偏移钳在 `[视口尺寸 - 图尺寸, 0]`。放大后仍能把任意角落拖到正中，同时"图被拖丢"这个状态不存在。
7. **缩放 5% ~ 1600%，滚轮每格 ×1.15**。
8. **双击**在"适应窗口"与"1:1"之间切换；**Esc 关闭**（走 `ICloseableView.RequestToClose`）。
9. **图片区背景固定近黑 `#FF1F1F1F`**，不跟随主题（亮色主题下浅灰底会让缩小的图与背景糊在一起）。
10. **全程 `HighQuality` 平滑插值**（放大到 1600% 也保持平滑，不切最近邻）。
11. **工具栏**：裸 `<Button>` + 主题隐式样式，图标用 `SegoeFluentIcons.ZoomOut`/`FitPage`/`ZoomIn`，`1:1` 用文字按钮（没有对应字形）；右侧显示缩放百分比 + 图片像素尺寸。不做键盘快捷键。
12. **无快照时不伪装成可点**：`Snapshot.Source` 为 null 时光标是箭头、无悬停高亮、无提示、点击无反应。
13. **面板做成通用的**：接口只依赖"一张 `ImageSource` + 一个标题"，以后别处要看图可直接复用。
14. **不做**：快照临时文件清理（老问题，见 `docs/code-review/2026-08-18-v2-review.md`；删除时机与主界面那张正锁着文件的图冲突，另案处理）、另存为/复制到剪贴板。
15. **不写单元测试**，但把缩放/平移的数学集中到一个不碰控件的静态类。
16. **验证只要求"能正常编译"**（见文末）。

## 实施方案

### 新增文件

| 文件 | 职责 |
|---|---|
| `SimpleFFmpegGUI.WPF/Panels/ImagePreviewMath.cs` | 纯数学静态类：锚点缩放、平移、适应窗口、1:1、钳制。输入输出只用 `double`/`Point`，不碰控件，便于将来单测与复核 |
| `SimpleFFmpegGUI.WPF/ViewModels/ImagePreviewPanelViewModel.cs` | `Title` / `Source` / `ZoomText` / `SizeText` + 一次性的 `SetImage(...)`。**缩放/平移状态不进 VM**（纯视图状态，无绑定需求） |
| `SimpleFFmpegGUI.WPF/Panels/ImagePreviewPanel.xaml(.cs)` | 视口 + 工具栏；鼠标/键盘/矩阵逻辑在 code-behind；含静态入口 `Show(owner, uri, title)`（读字节 → 解码 → 失败弹提示且不开窗）与"同一帧激活已开窗口"的静态表 |

### 布局约定（决定坐标系是否干净）

```
UserControl (Focusable, PreviewKeyDown, ICloseableView)
  Grid: Row * = 视口, Row Auto = 工具栏
    Border x:Name="viewport"  Background=#FF1F1F1F  ClipToBounds=True   ← 唯一的坐标参照系
      Image x:Name="img"  Stretch="Fill"
            HorizontalAlignment="Left" VerticalAlignment="Top"
            RenderTransformOrigin="0,0"  RenderTransform = MatrixTransform
    StackPanel: 缩小 / 1:1 / 适应窗口 / 放大 + 缩放百分比 + 像素尺寸
```

- 视口 `Border` 自身不加变换，所有坐标用 `e.GetPosition(viewport)`。
- `Image` 必须**左上对齐**，否则布局原点会带上居中偏移，所有公式都要补这一项。
- `Image` 用 `Stretch="Fill"` 并在加载后显式设 `Width/Height = PixelWidth/PixelHeight`，让"1:1"严格等于 1 图像像素 = 1 DIP（`Stretch="None"` 时元素自然尺寸会受 jpg 内嵌 DPI 影响）。
- `RenderTransformOrigin="0,0"` 必须显式写——**默认是 (0.5,0.5)**，不改则矩阵会绕元素中心缩放。

### 核心数学

屏幕点 `v`、缩放 `k`、平移 `Offset`：

- **光标锚定缩放**：`Offset' = v - (k'/k) * (v - Offset)`（光标下的图像点保持不动）。
- **平移**：`Offset += dv`。
- **适应窗口**：`k = min(vw/iw, vh/ih)` 再取 `min(k, 1)`；偏移取居中值。
- **1:1**：`k = 1`，以视口中心为锚，从"适应"切过去视觉连续。
- **钳制**：`iw*k <= vw` 时居中，否则 `Clamp(OffsetX, vw - iw*k, 0)`；纵轴同理。
- 缩放越界（`[0.05, 16]`）直接不改，**不做** clamp 后补位移。
- 百分比文案：`(k*100).ToString("0") + "%"`。

### 交互

- **滚轮**挂视口 `Border`（有 Background，始终可命中），`e.Handled = true`；不挂整面板，避免在工具栏上滚也缩放。
- **点击/双击/拖动**都在 `MouseLeftButtonDown` 分流：双击先释放捕获再切模式；否则开始拖动并 `CaptureMouse()`。`MouseMove` 里发现左键已松开就兜底释放捕获（自愈丢失的 up 事件），拖动期间光标切成四向移动。
- **Esc**：`PreviewKeyDown` 挂面板（焦点在工具栏按钮上时隧道事件仍经过面板），`e.Handled = true` 后触发 `RequestToClose`；`Loaded` 里 `Focus()`。
- **视口尺寸变化**：适应模式则重算适应，自由模式只重跑钳制。

### 解码（不锁文件）

`File.ReadAllBytes` → `BitmapImage`（`CacheOption = OnLoad`、`StreamSource` 为内存流）→ `Freeze()`，整段放 `Task.Run` 里在后台线程做（解码耗时取决于"快照尺寸"配置，默认 1080P 约几十毫秒，但设置页那个输入框没有范围校验，填成 2160P 就是几百毫秒；`BitmapImage` 后台解码 + `Freeze` 后交给 UI 线程是标准做法）。这样与文件完全解耦：主界面那张图继续锁着文件无影响，临时文件将来被清理也不影响已打开的窗口。

> **不要**设 `BitmapCreateOptions.IgnoreImageCache`：它只在 `UriSource` 路径下有意义（而快照文件每次都是新的 GUID 名，本就不需要绕 WPF 内部缓存），配 `StreamSource` 时 `EndInit()` 必定抛 `ArgumentNullException`——StreamSource 路径下 BitmapImage 内部的 `_uri` 是 null，而 IgnoreImageCache 会无条件拿它去 `RemoveFromCache`。已在 .NET 10 / PresentationCore 10.0 实测：加这一行每次开窗都失败（详见 `日志.md` 20260916 条目的复核记录）。

### 接线

`StatusPanel.xaml` 的快照 `Border` 加 `Cursor`/`ToolTip`/`MouseLeftButtonDown`，并加一个 `DataTrigger`（`Snapshot.Source` 为 `{x:Null}` 时还原光标并清掉提示）。`Border` 在 `DataTemplate` 里，用 `sender` 的 DataContext 取 `TaskInfoViewModel`（不能写 `x:Name`）。

标题：`快照预览 - {文件名} @ {时间点}`，时间点取 `SnapshotViewModel.Time`——由 `UpdateSnapshotAsync` 在写入 `Source` 时一起记下的**抓帧时刻**。不能用点击瞬间的 `ProcessStatus.Time`：快照最多十秒才刷新一次，那样标题描述的不是窗口里那张图。小时数按"天数×24+小时"算，`TimeSpan` 的 `hh` 格式会把超过 24 小时的素材位置回绕。严格说这是"**请求**取帧的位置"：`MediaInfoService` 用 `-ss`（输入 seek）+ `-skip_frame nokey`，实际取到的是 ≤ 该时间的最近关键帧，最大误差一个 GOP——这是取帧参数固有的近似，要消掉得改取帧方式，不在本次范围。

窗口：`new ViewWindow(panel, title, owner, 1100, 680).Show()`；`LimitInitialSize` 会把高度裁到属主可用高度，打开即"适应窗口"。

## 验证

按本次要求**只做到"能正常编译"**：`dotnet build SimpleFFmpegGUI.sln`（输出在 `Generation/bin/Debug/<项目名>`）。

鼠标手势部分由手工点验，重点看这几处：

- 打开预览窗口：图完整显示、居中，工具栏百分比与像素尺寸正确。
- 滚轮缩放时光标下的那个点不动（锚点是否准确）。
- 放大后拖拽能到任意角落；缩到比窗口小时自动居中且拖不动。
- 双击在"适应"与 1:1 之间切换；Esc 关闭。
- 同一帧重复点击只激活已开窗口；不同帧开新窗口。
- 任务刚启动、还没有第一张快照时，缩略图不是手型光标、点击无反应。
- 亮色/暗色主题下图片区都应是近黑底。
