# v2 分支代码审查报告（master_v2 @ 7ef581d）

- **审查时间**：2026-08-18
- **审查范围**：`SimpleFFmpegGUI.Core`、`SimpleFFmpegGUI.WebAPI`、`SimpleFFmpegGUI.WebTest`、`SimpleFFmpegGUI.Web`、`SimpleFFmpegGUI.WPF`、构建脚本与文档
- **方法**：4 个并行深度审查 + 实测验证（编译、前端构建、测试套件）
- **原则**：本报告只记录问题，不修改任何代码

## 一、实测验证结果

| 项目 | 结果 | 说明 |
|---|---|---|
| `dotnet build`（默认 Debug） | ❌ 24 错误 | `LocalFzLibPath` 指向 `C:\Users\$(USERNAME)\OneDrive\开发\FzLib\Publish\libs\FzLib.dll`，本机该路径不存在 → 所有 `using FzLib` 文件编译失败 |
| `dotnet build`（`-p:LocalFzLibPath=libs\FzLib.dll`） | ✅ 0 错误 / 47 警告 | **代码本身可编译**。警告多为 CS8632（nullable 注释未开 `#nullable`）、CS4014（async 未 await）、未用变量 |
| `dotnet build`（NuGet FzLib 3.3.2，即 Release 路径） | ❌ 9 错误 | NuGet 版**没有 `FzLib.Web` 命名空间**（`ServiceResult`/`HttpStatusCodeException` 只有新版本地 FzLib 有） |
| `npm run build`（Web） | ❌ 失败 | `tsconfig.app.json:6` 的 `"baseUrl": "."` 在 TypeScript 6.0 已废弃（TS5101），`vue-tsc` 直接退出 |
| `dotnet test`（WebTest，18 个测试） | ❌ 8 通过 / 10 失败 | 失败均为测试基建问题（见 A1/C3 组） |

**结论：v2 分支当前在标准环境下无法编译、无法构建前端、测试无法全绿。** 编译仅缺一个正确的 FzLib 引用配置（仓库内 `libs/FzLib.dll` 即为所需版本，且它含 `FzLib.Web` 命名空间）。

## 二、高严重度问题

### 1. 合并音视频任务被静默创建为"视频对比"任务（功能完全失效）⭐
- **位置**：`Core/Services/TaskService.cs:63`
- **问题**：`var taskType = type.ToLower() == "combine" ? TaskType.Mux : TaskType.QualityCheck;` —— v1 路由是 `Task/Combine`，v2 前端（`Web/src/api.ts:35`）已改发 `POST Task/Mux`，switch 里只可能匹配 `"Mux"`，`"mux".ToLower() == "combine"` 恒为 false → **type="Mux" 时恒创建 QualityCheck 任务**，且参数、输出路径均置 null。
- **影响**：Web 端"合并音视频"创建的任务实际跑视频对比的 ffmpeg 命令，用户无感知。测试无 Mux/Combine 用例，缺陷完全漏网。

### 2. 队列一次异常后永久瘫痪（cancelQueue 不复位）
- **位置**：`Core/Services/QueueService.cs:135-159`
- **问题**：`cancelQueue = false` 只在循环正常结束后复位；循环内任何未捕获异常（如任务被独立任务抢走导致的 NRE、DB 异常）都会跳过复位。
- **影响**：之后每次启动队列立即退出（只打"队列完成"），所有 Queue 状态任务永远不执行，无任何报错，需重启进程。`taskProcessManagers` 在保存失败时也会泄漏。

### 3. "默认进程优先级"是死功能（写入与读取两套配置源）
- **位置**：写入 `WebAPI/Controllers/ConfigController.cs:15-19`（ConfigService → config.json）、`WPF/ViewModels/SettingPageViewModel.cs:35-38`；读取 `Core/Services/FFmpegProcessService.cs:62`（`IOptionsSnapshot<AppSettings>` → appsettings.json）
- **问题**：没有代码把 ConfigService 的值传给 FFmpegProcessService；ConfigController.SetDefaultProcessPriority 也不调用 SaveAsync。v1 存 DB Configs 表、由 FFmpegManager 读取，重构后连接断裂。
- **影响**：Web 与 WPF 里设置均无效果，静默失效。

### 4. WPF 中两个 HostedService 从未启动
- **位置**：`Core/Services/DbLoggerService.cs:108-115`、`Core/Services/AppLifetimeService.cs:28-54`；`WPF/App.xaml.cs:84-88`（裸 `BuildServiceProvider()`，无 IHost）
- **问题**：v2 `AddFFmpegServices` 通过 `AddHostedService` 注册两个服务，WPF 不启动 IHost → 都不运行。
- **影响**：① `DbLoggerService` 的 10 秒周期日志落盘不执行 → **WPF 崩溃/强杀时本会话日志全丢**（仅退出时落盘一次）；② `AppLifetimeService` 的"启动时复位遗留 Processing 任务"不执行 → **上次异常退出遗留的任务永远卡"处理中"**（WebAPI 会复位，WPF 不会）。

### 5. WPF「添加到远程主机」功能三重失效（v1 协议未适配 v2）
- **位置**：`WPF/ViewModels/AddTaskPageViewModel.cs:58-84, 222-288`
- **问题**：
  1. 认证头发裸 token（`:69`），v2 `AppActionFilter.cs:60` 要求 `Bearer {token}` → 配置了 Token 必 401
  2. 请求体属性名 `Argument`（`:260-265`），v2 `Core/Dto/TaskDto.cs:11` 已改 `Parameter` → 绑定不上，参数为 null
  3. 输入路径 `":"` 前缀约定（`:253-257`），v2 `Core/Helpers/FilePathHelper.cs:25-33` 无对应处理 → 404"输入文件不存在"
- **影响**：UI 保留的远程主机功能整体不可用。

### 6. WebTest 整套测试在干净环境无法运行（三层叠加）
- **位置**：`WebTest/SimpleFFmpegWebApplicationFactory.cs:30-106`
- **问题**：
  1. `PrepareTestVideos`（63-106）要求测试输出目录下有 `ffmpeg\ffmpeg.exe`，仓库 `bin/ffmpeg/` 只有占位 `files.txt`，csproj 无拷贝逻辑 → 直接 `throw new Exception("ffmpeg.exe 不存在")`
  2. 测试视频 `DJI_20260121131244_0057_D.MP4`（appsettings.test.json）仓库中不存在
  3. 测试进程 `Program.Main` 在 `builder.Build()` 被 `HostAbortedException` 中止 → `InitializeDatabase`（唯一 `EnsureCreated`）不执行；`AppLifetimeService.StartAsync` 启动时查 `db.Tasks` → 新机器 `db_test.sqlite` 无表 → SqliteException → host 启动失败
- **影响**：所有测试类在 fixture 阶段整体失败；CI 不可能通过。

### 7. AppActionFilter 异常处理两处问题
- **位置**：`WebAPI/AppActionFilter.cs:32-40`
- **问题**：① 非 `HttpStatusCodeException` 异常只要 Message 非空就 `ObjectResult(Message){500}` 回客户端——SQLite/EF/IO 异常含完整文件路径、SQL 片段等内部信息直接暴露；② 异常 Message 为空时 `ExceptionHandled=true` 但 `Result=null` → **返回 HTTP 200 空响应**，错误被静默吞掉。
- **影响**：信息泄露 + 错误语义不一致（空 200 让前端误判成功）。

### 8. 发布管线断裂：build.ps1 / README 仍在发布已删除的 Host 项目
- **位置**：`build.ps1:69-73`、`ReadMe.md:10-14, 39-42, 47, 95`
- **问题**：v2 已删除 Host/Host.Console/Host.WindowsService，脚本仍 `dotnet publish` 三个不存在的项目 → `-w` 必然失败，WebPackage 无法生成。README 仍指导"启动 Host"、仍文档化已删除的 `InputDirAccessable/OutputDirAccessable` 配置、仍写"NamedPipe IPC"。
- **影响**：用户按文档无法部署；发布脚本不可用。`CreateWindowsService.bat` 虽已更新为注册 WebAPI.exe，但 build.ps1 从不把它拷进发布包。

### 9. 任意路径读写（路径穿越）：FilePathHelper 无目录包含校验
- **位置**：`Core/Helpers/FilePathHelper.cs:25-33`
- **问题**：全限定路径原样返回、相对路径直接 `Path.Combine`，均不校验 `..` 段、不校验结果是否仍在 rootDir 内。
- **暴露面**：`FileController.Download`（下载服务器任意文件）、`FileController.UploadFile`（`file.FileName` 可含 `..\` 写出 rootDir）、`MediaInfoController.GetAsync`。唯一屏障是 token。
- **影响**：持有 token（含默认 token，见下）即可任意读/写服务器文件系统。

### 10. 出厂配置携带默认 Token "123456" 与作者本机绝对路径
- **位置**：`Core/appsettings.json:15-21`（经 csproj `CopyToOutputDirectory/PublishDirectory` 进入发布包）
- **问题**：`"Token": "123456"` 公开已知；`InputDir/OutputDir` 指向 `C:\Users\autod\Desktop\output`（作者桌面路径，不存在）。
- **影响**：部署后不改配置 = 远程控制服务使用公开默认口令；文件操作全部 404/500。

## 三、中严重度问题

### 11. 启动顺序与日志盲区：MigrateDb 在 InitializeLogs 之前
- **位置**：`WebAPI/Program.cs:72-75`
- **问题**：`Log.Logger` 只在 `InitializeLogs` 赋值；此前异常（ConfigureServices/MigrateDb/EnsureCreated 失败）走 `Log.Fatal` 时 Serilog 还是默认静默 logger → 消息丢失。`MigrateDb` 内部吞异常只写 Console.Error 后 `Environment.Exit(-1)`。
- **影响**：数据库迁移失败等启动错误在生产几乎不可诊断。

### 12. Serilog 未接入 host 日志管线
- **位置**：`WebAPI/Program.cs:94-109`
- **问题**：`builder.Logging` 未加 Serilog provider；ASP.NET Core 自身 ILogger 输出（Kestrel/EF/中间件异常）全走默认 Console，不进 `logs/logs.txt`。

### 13. 预设"编辑/更新"功能完全损坏（前端未接线更新接口）⭐
- **位置**：`Web/views/Presets.vue:87-98, 104-108`、`Web/components/CodeArguments.vue:263-284`、`Web/api.ts:122-124`
- **问题**：前端所有"保存/更新"路径都调 `POST /Preset`（新建）；后端 `PresetService.AddPresetAsync` 对同类型同名返回 **409**；后端专门提供的 `POST Preset/{id}` 更新接口前端从未调用。编辑对话框也无名称输入框。
- **影响**：预设点"编辑"保存必然 409，只能新建和删除。

### 14. 未登录时所有请求携带 `Authorization: Bearer undefined` → 401
- **位置**：`Web/App.vue:188`、`Web/api.ts:264-266`
- **问题**：`setHeader()` 无条件执行，cookie 缺失时拼出 `Bearer undefined`；后端 `AppActionFilter.cs:53-64` 将其判为"Token不正确"（该分支本身就像是为这个 bug 打的补丁）。
- **影响**：配置 Token 的部署下，未登录访问任何页面先弹一串"Token不正确"错误再跳登录页。

### 15. `processedOptions` 字段名残留（v1 字段名）
- **位置**：`Web/components/CodeArguments.vue:371`、`CodeArgumentsDescription.vue:98,100`
- **问题**：v2 后端属性已改 `ProcessedOperationParameters`（JSON：`processedOperationParameters`），前端读取处仍用旧名 `processedOptions`。
- **影响**：加载预设/任务回填时"同步文件时间/删除输入文件"设置被静默丢弃；详情页两行恒显示"否"。

### 16. Mux"长度处理"开关是死控件
- **位置**：`Web/components/CodeArguments.vue:22-30, 310-318, 365-367`、`CodeArgumentsDescription.vue:77-82`
- **问题**：前端 `getArgs()` 从不序列化 `combine.shortest`；后端 `FFmpegTaskService.RunCombineProcessAsync` 也不读 `MuxParameters.Shortest`（仅旧数据转换在用）。
- **影响**：用户切换"裁剪到最短媒体的长度"无任何效果；详情页恒显示"静帧或黑屏"。

### 17. SyncModifiedTime 分支缺 Inputs 空判断（自定义任务 NRE）
- **位置**：`Core/Services/FFmpegTaskService.cs:240-245`
- **问题**：`task.Inputs[^1]` 无输入时抛异常；对比 254 行 DeleteInputFiles 分支有 `Count > 0` 守卫，此处没有。Custom 任务（允许 Inputs=null）+ 勾选"同步修改时间"即触发。
- **影响**：该组合必然失败。

### 18. 取消/暂停在任务"准备中"窗口 NRE
- **位置**：`Core/Services/FFmpegTaskService.cs:148-153, 158-171`（CTS 在 RunAsync 才初始化、Process 在 442 行才创建）、`Core/Services/QueueService.cs:85-102`
- **问题**：任务被队列认领到 RunAsync 执行之间存在窗口，此时取消 → `cancel.Cancel()`/`Process.WaitForExitAsync()` NRE，API 500，任务继续跑完并写回 Done（覆盖已写的 Cancel）。
- **影响**：偶发取消失败，状态不一致。

### 19. 默认输出路径落到输入目录而非 OutputDir
- **位置**：`Core/Services/TaskService.cs:191-218`（GetOutputByInput）
- **问题**：输入路径在 37/56/75 行已被改成绝对路径，`GetFullPath(OutputDir, 绝对路径)` 因 `Path.IsPathFullyQualified` 原样返回 → 输出生成在输入文件旁边。v1 是 `Path.Combine(OutputDir, GetFileName(...))`。
- **影响**：与 v1 行为不一致；配置了输出目录的用户发现输出在输入目录（去重逻辑避免覆盖输入）。

### 20. v1 预设 JSON 导入不修复 Type=3（Custom）枚举值
- **位置**：`Core/Compatibility/PresetConverter.cs:42-51`（原样透传 old.Type）；对比 `DatabaseMigrator.cs:177-190` 专门做 3→99
- **问题**：v1 导出的 Custom 预设 JSON `"Type":3`，v2 TaskType 无 3（99 才是 Custom）→ 导入后预设消失、用它建任务抛 `NotSupportedException("不支持的任务类型：3")`。
- **影响**：v1 自定义预设"导入"恢复时静默损坏（DB 迁移路径无此问题）。

### 21. MediaInfoService 预设推断有未捕获 KeyNotFoundException
- **位置**：`Core/Services/MediaInfoService.cs:47-146`
- **问题**：`settings["rc"]`、`settings["subme"]`、`settings["ref"]` 等在 try/catch 之外直接索引，x264/x265 的 encoding settings 不一定含这些键。
- **影响**："读取编码设置转为输出参数"对部分源文件直接 500。

### 22. QueueService 的 Managers 列表无同步
- **位置**：`Core/Services/QueueService.cs:32, 244-254, 340-354`
- **问题**：普通 `List` 由队列线程和并发独立任务增删，`Managers`/`Tasks` 属性与 `TaskService.cs:123-125` 无锁枚举；`TaskManagersChanged` 事件在后台线程触发。
- **影响**：多任务并发/浏览列表时偶发 InvalidOperationException。

### 23. 任务/队列测试不稳定：真实时间 sleep + 机器级 ffmpeg 进程计数
- **位置**：`WebTest/TaskAndQueueApiTests.cs:33-47, 64-72, 202`
- **问题**：计划 5 秒执行 + 固定 `Task.Delay(8s)` 后断言 Processing（快机器已完成、慢机器不够）；`GetProcessCount()` 统计整台机器所有 ffmpeg 进程，机器上同时跑其它 ffmpeg 时断言失效。
- **影响**：偶发红/偶发绿，结果不可复现。

### 24. CompatibilityMigrationTests 静默假通过
- **位置**：`WebTest/CompatibilityMigrationTests.cs:40-49`
- **问题**：`FindTestDbPath()` 找不到 `test/old_db.sqlite`（该文件不在仓库）时 `output.WriteLine("跳过测试"); return;` → 测试以 Pass 收场，迁移逻辑实际从未执行。
- **影响**：v1.1→v2.0 数据库迁移（涉及真实用户数据改写）零覆盖，绿灯给人错误信心。

### 25. 迁移的降级处理与配置丢失
- **位置**：`Core/Compatibility/DatabaseMigrator.cs:160-164, 195-200`
- **问题**：① 单行 JSON 反序列化失败静默替换为默认 OutputParameters，仅 Console 输出（WPF 无控制台不可见）→ 参数丢失；仅 catch JsonException，其他异常中断整个迁移并回滚；② 直接 DROP Configs 表，v1 存在其中的 DefaultProcessPriority、SnapshotSize 等用户设置未迁移（v2 MediaInfoService.cs:181 硬编码 "-1:1080"）。
- **影响**：用户配置静默丢失。

### 26. FTP 匿名认证且默认端口写死
- **位置**：`Core/Services/FtpService.cs:58-60`、`appsettings.json:17-18`
- **问题**：`EnableAnonymousAuthentication()`；固定端口 36734/36735。
- **影响**：开启 FTP 后任何能到达端口的客户端可匿名读写输入/输出目录。

### 27. v1 的 InputDirAccessable 回退机制整体移除（架构后果）
- **位置**：v2 已删 PipeClient/CanAccessInputDir，`FileController.GetInputFiles` 直接 `Directory.EnumerateFiles`；README 仍教用户配置已不存在的 `InputDirAccessable`
- **影响**：IIS 应用池无权限访问网络共享目录的部署形态（v1 支持）在 v2 直接 500，且无降级路径。需明确部署要求：WebAPI 必须与被控机器同机或有文件权限。

### 28. 生产环境无全局异常处理
- **位置**：`WebAPI/Program.cs:153-158`
- **问题**：只有 Development 有 `UseDeveloperExceptionPage`，无 `UseExceptionHandler`；中间件层异常在 Production 直接空白 500，且不写文件日志（见 12）。

### 29. Debug 构建依赖作者个人 OneDrive 路径（他人无法编译）⭐
- **位置**：`Directory.Build.props:11-12`（`UseLocalFzLib=true` 默认 + `LocalFzLibPath=C:\Users\$(USERNAME)\OneDrive\开发\FzLib\Publish\libs\FzLib.dll`）；Core/WebAPI/WebTest csproj 均按此条件引用
- **问题**：任何非作者机器上 `dotnet build`（默认 Debug）引用不存在的 DLL 直接失败。
- **补充**：**版本漂移**——WPF 固定引用 `libs/FzLib.dll`（3.4.0-rc.2，且引用重复写了两遍 `WPF.csproj:44-49`），Core/WebAPI Release 走 NuGet FzLib 3.3.2 → 发布包中同名 DLL 互相覆盖，存在运行期 MissingMethodException 风险。

## 四、低严重度问题（节选）

- **前端 `npm run build` 失败**：`tsconfig.app.json:6` baseUrl + TS6 弃用（TS5101）。修复：删 baseUrl 或加 `ignoreDeprecations: "6.0"`。
- **README 与实现多处不符**：声称 vite 代理实际无 proxy（`vite.config.ts` 仅 port 8080，开发模式硬编码 `http://localhost:5001` + CORS）；`Web/README.md` 仍是 Vite 模板默认文案；`/password` 残留路由（`router/index.ts:31`）；路由无 beforeEach 守卫。
- **`process.env.NODE_ENV` 残留**（`api.ts:6`、`utils/navigation.ts:12`）应改 `import.meta.env`。
- **FFmpegLib 死代码**：`GeneralVideoCodec.cs:23` return 后不可达 throw；`MaxSpeedLevel=10` 而 `FFmpegEnums.Presets` 只有 9 个元素（speed 9/10 会 IndexOutOfRange）；`N_VideoCodec.cs:7` 抛 NotImplementedException（性能测试用即崩）。
- **死代码/残留**：`FFmpegDbContext` 无参构造函数（new 出即不可用）、`Check()` 无调用者、注释掉的 Migrate 段；`AppSettings.cs:15` `LocalSqlite` 属性永不绑定（配置在 ConnectionStrings 节）；`App.vue` 死接线（`statusChanged` 事件无人 emit）；`public/index.html` 为 vue-cli 残留。
- **可移植性**：`AppTestSettingsKeys.cs` 整段注释；`libs/ModernWpf.FzExtension.dll`、`WindowsAPICodePack.FzExtension.dll` 无引用（孤儿 DLL）。
